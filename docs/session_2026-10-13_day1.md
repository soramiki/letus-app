## 📝 アプリの構想（最初に用意した CLAUDE.md の要点）

詳しくはプロジェクト直下の `CLAUDE.md` を参照。

### 一言で
LETUSの課題と、口頭や紙で出された課題をまとめて管理し、「いつ始めるか」まで示して、取りこぼしとギリギリ提出を防ぐ。
想定ユーザーはLETUSを使う大学生（スマホでの利用がメイン）。

### 解決したい不便
1. LETUSはログインが毎回必要で、開くのが面倒
2. LETUSは通知してくれないので気づきにくい
3. 口頭で言われた課題はダッシュボードに載らず、見落とす
4. いつやるかを決めていないので、提出がギリギリになる

### 画面構成
| 画面 | 内容 |
| --- | --- |
| ホーム | 今日の要約（期限切れ／今日締切／今日始める の件数）＋ 科目ごとのタイムライン |
| 一覧 | 検索・絞り込み・並び替え |
| 追加・編集 | モーダル（画面に重ねて出す小窓）。科目・課題名・締切だけで登録できる |
| 取り込み | LETUSから書き出した .ics ファイルの読み込みと、手順の説明 |

### 主な決まりごと
- 保存先は LocalStorage（ブラウザの中の保存場所）。PCとスマホの同期はしない
- 「始める日時」は自動計算（基本は締切の2日前18時。開始から締切まで1日しかなければ前日18時）
- .ics の取り込みでは、UID（予定ごとの固定の番号）で同じ課題かを見分け、締切の延長にも対応する
- 取り込みでは、ユーザーが付けた完了チェックを書き換えない

- 要項から CLAUDE.md の「課題（社内）の条件」に追記した主な点：
  - **GitHub・Vercelは個人アカウント**（会社のアカウントは使わない）
  - 初回公開のあと、Pushで Vercel が自動更新されることも確認する
  - **ログインなしで代表が主な機能を試せること** → 架空のサンプルデータや sample.ics を用意する
  - AIの利用はOKだが、**生成したコードを自分で説明・修正できること**／振り返りに使ったAIツールと用途を書く
  - 完成後にデモをする。評価は**機能の多さより完成度**
- 要項の全文は、Publicのリポジトリに入れないため保存していない（要点だけ CLAUDE.md に書いた）。

## 📘 今日おぼえた言葉

- **リポジトリ**：GitHub上のコードの保管場所
- **Push**：手元のコードをGitHubにアップロードすること
- **コミット**：Gitで今の状態を記録すること（セーブポイント）
- **.gitignore**：Gitに入れないファイルのリスト
- **Vercel**：GitHubと連携して、Pushするたびに自動でサイトを公開・更新してくれるサービス
- **LocalStorage**：ブラウザの中の保存場所。端末・ブラウザごとに別々
- **モーダル**：画面の上に重ねて出す小窓
- **State（ステート）**：画面の状態を覚えておく箱。中身が変わると画面が描き直される
- **コンポーネント**：画面を部品に分けたもの（TaskList、TaskItem など）
- **カスタムフック**：useState などを組み合わせて、使い回せる形にしたもの（useTasks）
